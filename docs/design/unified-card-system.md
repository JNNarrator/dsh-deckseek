# 统一卡片体系（Unified Card System）

> **已被 [reading-skins.md](reading-skins.md) 取代（2026-09-11）**。本文描述的三档卡片体系并入「软卡」皮肤，其左缘色条在软卡中被移除；`--dsh-card-*` token 由 `--dx-*` 取代。本文保留作历史记录，不再更新。
>
> 设计稿：2026-09-10 讨论定稿。**第一版已实现（0.6.2）**，待观感评审后按下方"待迭代判断的点"调整。
> 起因：阅读视图混用气泡、卡片、色块、透明行与碎片五种表面处理，圆角出现 8 种取值（6/7/8/9/12/16/22/50%），观感凌乱。

## 目标

一套卡片语言覆盖阅读区全部元素：**统一**（同一套卡壳、同一套圆角与边框规则）**但类型明显区分**（靠档位体量、左缘色条、图标）。

范围包含用户消息（原气泡也改为卡片）。工具栏、搜索面板、历史按钮、空状态、回到底部圆钮、右侧导轨、复制悬浮芯片不进卡片体系——它们是操作面不是内容。

## 宿主 token 约束（决定设计形态的关键事实）

宿主 `ui-theme` 的底色层级在**亮色主题下是平的**：

| token | 亮色 | 暗色 |
|---|---|---|
| `--dsw-alias-bg-base` | `rgb(255,255,255)` | `rgb(21,21,23)` |
| `--dsw-alias-bg-layer-1 / 2 / 3` | 三者均 `rgb(255,255,255)` | 875 / 850 / 800（有分层） |
| `--dsw-alias-bg-module-platform` | `rgb(245,246,247)` | `rgb(53,54,56)` |
| `--dsw-alias-interactive-bg-hover` | `rgba(38,49,72,.06)` | `rgba(255,255,255,.08)` |
| `--dsw-alias-interactive-bg-hover-danger` | `rgba(236,19,19,.05)` | `rgba(242,90,90,.15)` |
| `--dsw-alias-border-l2` | `rgba(0,0,0,.1)` | `rgba(255,255,255,.12)` |

`bg-layer-*` 在亮色下三者相同，`module-platform` 与两种 hover tint 叠在白底上也都落在 #F2–F5 之间。**亮色主题实际只有一个可用的抬升底色**，因此档位不能做成底色深浅阶梯，只能按形态分档；底色只在"卡 / 面板"两级上分。

约束：只用宿主 `--dsw-*` token，不新增插件自己的色板。彩色只给带状态的卡片（失败 / 待确认）与用户卡，内容类靠图标、字重、体量区分——语义 token 里可作强调色的本就只有三种左右，硬凑五色会让色条彼此近似。

## 三档

| | 内容档 | 记录档 | 状态档 |
|---|---|---|---|
| 含义 | 读者要读的东西 | 执行过程与元信息 | 需要被注意到的事 |
| 底色 | `bg-module-platform` | `bg-layer-1`（宿主层级阶梯的次级容器；暗色 #232323，亮色白 + 发丝线） | 语义 tint：危险=`red-500`@10%、待确认=`interactive-bg-hover-accent`、notice=`module-platform` |
| 边框 | `border-l2` 1px | `border-l1` 1px（发丝线，暗色 rgba(255,255,255,.06)） | 无 |
| 圆角 | 12px | 12px | 12px |
| 内边距 | 12 / 16 | 8 / 12 | 10 / 14 |
| 左缘色条 | 用户不用色条——**底色即身份**（`specific-bubble` 填充）；回答无；推理中性 | 中性（`border-l3`） | 失败/错误=`static-red-500`；待确认=`state-business-primary`；notice 中性 |
| 图标 | 用户、推理有；回答无 | 有 | 有 |

> 0.6.4 修订：记录档底色从 `module-platform` 降到 `bg-layer-1` 并加发丝线（评审反馈"灰色块一片平、缺乏主次"）；危险 tint 改为 `color-mix(red-500 @ 10%)`、红色只留在色条与标题，正文用普通墨色 + 等宽字体（原整卡红字对比度差、观感"脏"）。

圆角尺度收起为三级：**卡片外壳 12 · 卡内面板 8 · 芯片 6**（原 7/9/16/22/50% 归并；回到底部圆钮仍是圆形控件，不在此列）。

## 卡片骨架

三档共用骨架，只有"有没有标题行、拿不拿颜色"随类型变：

```
┃ ◐  推理 · 2.4s                              跟随 ⌄      ← 标题行（可选）
┃    先确认 clippy 的报错来源……                            ← 主体
┃    ⌄ 查看原始记录                                        ← 披露（可选）
```

- **用户卡**：无标题行，**底色=`specific-bubble`（宿主自己的用户消息身份色），不用色条**，图标 `IconUserOutline16`
- **回答卡**：无标题行、无彩条、无图标（正文即内容，是默认档）；右上悬浮复制芯片保持现状
- **推理卡**：标题行（`IconThinkOutline16` + 时长 + 跟随控件），中性色条
- **记录卡**：标题行（工具图标 + 工具名 + 摘要 + 右对齐状态字），中性色条
- **状态卡**：标题行（警示图标 + 标题，如「工具执行失败 · edit」），语义色条，可选 code 芯片与「查看原始记录」

## 元素归位

- **内容档**：用户消息、回答卡、推理卡
- **记录档**：工具行（工具调用 + 状态）、工具详情面板、未知记录、系统提示、压缩记录、图片帧、轮次统计与 meta 行（思考与过程 / turn-process / turn-tail）
- **状态档**：失败卡（工具 / 回合 / 命令 / 压缩）、notice（终态行、长度限制、重试中、位置恢复、历史失败）、待确认 attention、已停止芯片
- **控件层（不卡片化）**：工具栏、搜索面板、历史按钮与骨架、空状态、回到底部圆钮、右侧导轨、复制悬浮芯片

## 实现规则

1. **色条用内阴影实现**（`box-shadow: inset 3px 0 0 <color>`），不用 `overflow: hidden` —— 回答卡的复制芯片悬浮在卡片右上角、会溢出边界，裁剪会把它切掉。
2. **图标 14px，与色条同色；中性色条配次级文字色图标。** 图标、色条这类"墨"只能用文字/状态 token（`label-*`、`state-*`），不能用表面 token——`specific-bubble` 在暗色下是 `bluish-850`，叠在 `bluish-800` 的卡片上完全隐身（第一版实际踩过：用户卡图标不可见，左侧留出一大段空当）。
3. **卡内面板降级**：卡片内部的面板（工具详情、原始 JSON、未知记录预览、系统提示正文、图片帧）改为 `bg-base` + `border-l2` + 圆角 8。它们现在与卡片同用 `module-platform`，卡片换底色后会糊成一片；降为 base 后亮色是"灰卡上的白面板"、暗色是"深灰卡上的更深面板"，两个主题方向一致，都读作内嵌。
4. **披露控件统一**：所有展开入口（查看原始记录、全部输入字段、原始数据）都是正文最后一行，同字号、同箭头间距，距正文 8px。

## 边界

- 回答卡内的 **Markdown 代码块不改**：由宿主 `ui-primitives` 渲染，`DESIGN.md` 要求保留原生渲染器。规则 3 只适用于 deckseek 自有面板。
- 不改动折叠语义、动效时长、28px 视口遮罩、14px/24px 状态标签等 `DESIGN.md` 已规定的行为契约。

## 验收

- `npm run typecheck` 零错误、`npm test` 全绿（现有 101 项 + 新增表面映射断言）。
- `DSHX_HARNESS=<带 tools/dshx 的检出> npm run build` 成功，装入 web profile 后启动无错。
- 视觉项（档位体量、色条、圆角）需在本地 DSH 里过一眼，亮/暗两个主题各看一次。

## 待迭代判断的点（第一版后按观感定）

1. **记录档里的 meta 短行**（思考与过程、轮次统计）加上卡壳后是否过噪——这是本次最容易显得啰嗦的一处。
2. 回答卡无图标、无彩条，是否仍能被辨识为"主内容"，还是需要一条中性色条。
3. 圆角统一到 12px 后，用户卡（原 22px 气泡）的对话感是否足够。
4. 工具行进记录档后变高，长会话的密度是否可接受。

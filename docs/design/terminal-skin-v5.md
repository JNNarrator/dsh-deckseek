## 这一轮的判断

那份清单里有三类东西，必须分开对待，否则会做成"看起来做了很多、其实一半是假的"：

1. **本插件能做的**：骨架（状态栏、字符边框、ANSI 角色色、braille 旋转）、交互（键盘层、
   命令面板、快捷键面板）。这一轮全做了。
2. **宿主所有权所限、插件改不到的**：输入框与斜杠命令、审批 `[y]/[n]/[e]/[a]`、
   应用级状态栏（模型 / token / 成本 / 连接）、`[1] Chat [2] Workflow [3] Logs` 页签。
   这份清单里的"命令输入""审批""状态栏数字"三项主要落在这一类，
   `reading-skins.md` 的「受宿主所有权所限」一节早有记录，本轮不改结论，只把它写进下面的表。
3. **需要分母才成立的**：进度条 `[████░░] 67%`。我们没有总量，只有"已经发生的步骤"，
   所以不做量表，只做**有分母的那一半**（折叠摘要已经给"多少次调用 / 多少个文件"）。

用户自己的收尾建议是「先做骨架，再加主题和动效」，本轮就按这个顺序：**T1–T6 是骨架与交互，
CRT/扫描线/霓虹这一层留给下一轮**（见「明确不做」）。

## 一句话

**GUI 里做 TUI 皮肤 = 终端美学 + GUI 交互能力。** 本轮补的正是后半句：在此前只有"终端样子"
的基础上，加上一套真正能用键盘走完的操作面（命令面板、快捷键面板、`j/k/g/G//` 导航），
以及一条常驻状态栏。

## 用户清单逐条处置

图例：✅ 本轮做了 · 🟡 已有（此前版本已在） · ⛔ 宿主所有权所限 · 🅿️ 有意不做 · ⏭ 下一轮

### 一、核心设计原则

| 原则 | 处置 |
|---|---|
| 等宽字体 + 网格布局 | 🟡 终端皮肤自 v2 起整列等宽（`.column` 一条竖轴） |
| 键盘优先，鼠标增强 | ✅ 新增统一键盘层（T4）；每个键盘动作都同时有可点控件 |
| 状态永远可见 | ✅ 新增底部状态栏（T3）：`RUN` / `WAIT` / `IDLE` + 读数 + 两个面板键 |
| 信息密度高但不乱 | 🟡 块间距 8 / 组内 4–6 |
| GUI 能力保留 | ✅ 可复制、可搜索、可折叠、可导出；**全部 DOM 文本，无 canvas** |
| 动效克制 | 🟡 逐皮肤动效 token + `data-motion=off`；本轮只加了 110ms braille 旋转与 120ms 面板淡入 |

### 二、视觉元素

| 建议 | 处置 |
|---|---|
| 等宽字体表（JetBrains Mono / Fira Code / …） | 🅿️ 字体栈由宿主提供（`--ds-font-family-code`）；插件不指定字面字体名，否则会与宿主设置打架 |
| Nerd Font 图标 | 🅿️ 字形表是**单格宽纪律**（`tests/skin-css.test.ts`），Nerd Font 私有区码位宽度不定，会撕裂列对齐。沿用 braille 与单格标点 |
| ANSI 16 色 | ✅ **角色层**（T2）：`--dx-ansi-*` 九个角色，**每个角色都绑到宿主 token**（`tests/skin-css.test.ts` 强制）。用户已确认这条：观感要 ANSI，颜色契约不破 |
| 字符边框 `┌ ┐ └ ┘` 等 | ✅ 窗口四角用字形画（T1）；双线 `╔═╗`、圆角 `╭─╮`、ASCII `+--+` 不做——一种边框就够了，多一套只是选项噪音 |
| 光标 `█ ▓ ▒ ░ _ |` | 🟡 流式回答末行 `▌` 方波光标（v3） |
| 进度条 `[████░░] 67%` | 🅿️ 没有分母，见上文第 3 类 |
| Spinner `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` | ✅ braille 旋转（T5），逐帧单格宽，**没有固定 1ch 裁剪窗口**（v3/v4 否掉逐帧轮转的技术原因就是那个窗口） |
| 状态图标 `✓ ✗ ⟳ ○ ! ? ●` | 🟡 `▸ / ✓ / ✗` 三态（工具行）、`⏺ ⎿ ✻`（词汇表）；`○` 未开始、`⟳` 进行中不新增——折叠行已经用状态字说明 |
| 树 `├── └──`、表格 `│ ─ ┼` | 🅿️ 我们没有目录树；表格由宿主 `ui-primitives` 渲染，插件不接管（既有不变式） |
| CRT 扫描线 / 辉光 / 暗角 | ✅ T7（默认关，见第二节） |
| 噪点 / 屏幕曲率 | 🅿️ 见「明确不做」 |
| 亮度默认低、提供「减少动态」 | 🟡 「减少动态」已有：工具栏按钮 + 命令面板 + `prefers-reduced-motion` |

## 不破的不变式

- **React 里没有皮肤分支**：`.statusBar`、工具栏的两个面板键全部**始终渲染**，
  由 CSS 按皮肤显隐（`display: none` / `display: flex`）。所以测试能断言它们在树里，
  CSS 契约测试能断言它们只在终端皮肤出现。
- **颜色只取宿主 token**：新增的 9 个 ANSI 角色本身也是 token，取值全是指向 `--dsw-*` 的
  `var()`；`tests/skin-css.test.ts` 新增一条把它们沿别名链一路解到宿主 token 为止。
- **颜色只表达状态 + 会改变什么**：本轮没有新增上色用途；提示符（成功率色）、路径（信息色）
  是"这是什么"，与既有的"状态 / 会改变什么"同一条语义。
- **动效可停**：braille 旋转由 JS 按 `motion` 决定转或不转（不转时定格在第一帧），
  面板淡入由 `[data-motion=off]` 与 `prefers-reduced-motion` 关掉。
- **活区只有一个**：状态栏**不是** `role="status"`。阅读页已经用 `.statusText` 里的
  `role="status"` 播报相位，第二个 polite 活区会随每次工具调用重复播报，把屏幕阅读器用废。
  状态栏是"读数"，就读在它所在的位置。

## 实施记录（与计划的出入）

1. **`Ctrl+F` 的守卫从"只认 Ctrl"改成"Ctrl/Cmd + 不带 Shift"**。原来的监听把
   `Ctrl+Shift+F` 也当成查找；浏览器与宿主 devtools 都要用这个组合，键盘层顺手把它让出去了。
2. **命令面板的 Enter 只在面板自己的子树上读**（React `onKeyDown`）。测试里一开始把 `Enter`
   打在 `window` 上，结果面板收不到——真实浏览器里 keydown 从持有焦点的输入框冒泡上来，
   测试必须打在输入框上。这条差异写进了测试注释，免得下一个人以为全局监听漏了键。
3. **`q` 只在焦点不在输入框时才是"关闭"**。`j/k/g/G/q` 这一组是"无修饰的裸键"，
   而在命令面板里打字时它们必须是文字——所以 `keymap.ts` 先看 `typing`，再看 `panel`。
   快捷键面板把焦点放在关闭按钮上，因此在它打开时 `q` 仍然能关掉。
4. **braille spinner 没有用 CSS `content:`**。v3/v4 记录过：CSS Modules 会哈希 `@keyframes`
   的名字，且固定宽度裁剪窗口会撕裂宽字形。这次字形是 React 渲染的文本节点，宽度由字体自然给出，
   旋转只是换一个同宽的码位——两个坑都绕开了。`content:` 只留给角落字形与 `· ` 分隔符。
5. **状态栏的读数在 520px 容器下整段隐藏**，与既有 `statusClock`（480px）同一思路。

## 交付途中的一次构建事故（2026-09-29）

**现象**：装上 0.2.0-rc.1 对应的包之后，阅读页**每一轮被横向并排**，每列只有**一个字符宽**，
中文竖着排（`你自己视觉过一遍吧` 变成一列单字）。窗口框、顶栏、底栏却是正常的全宽。

**根因**：不在插件源码，也不在宿主，而在**为这次开发临时自建的 dshx 替身**
（`scripts/css-modules.mjs` 的前一版）。它的 CSS Modules 变换把"重命名"做成了**整表按裸词替换**：

```css
/* 源码 */            flex-direction: column;
/* 变换后（错） */     flex-direction: _ekqmtO_column;
```

`_ekqmtO_column` 不是合法的 `flex-direction` 值，浏览器**整条声明丢弃**。于是
`.column` / `.turn` / `.mainFlow` / `.blocks` / `.answer` 全部从 flex column 退化成 flex row ——
每一轮变成一行里的一列，各自被压到 min-content（一个汉字）。基线包（真 devkit 产出）里
`flex-direction:column` 有 23 处，我的包里 **0 处**。

**为什么四道关卡全都没拦住**：

| 关卡 | 为什么看不见 |
|---|---|
| `npm test` | 测试的 CSS loader 是 Proxy 桩，返回属性名，**从不执行变换** |
| `tsc --noEmit` | 类型检查看不到样式表 |
| `tests/skin-css.test.ts` | 读的是**源码**样式表，而源码是对的 |
| 我用来"视觉过一遍"的本地预览 | 它用的是 `scopeCss(css, '')`（空前缀），而空前缀下"把 `column` 替换成 `column`"是**恒等操作** —— 这份预览在结构上就不可能看见这个 bug |

最后一条是最值得记的：**预览必须走与产物同一条变换**，否则它验证的是一个不存在的东西。

**修复**：

1. 变换改为**结构化遍历**：带上下文栈走 `{}`，类名只在**选择器文本**里重命名，声明值一律不动。
2. 动画名重写改成**第二遍**再做：`.railTip` 用 `railTipIn` 的地方在 `@keyframes railTipIn` 之前，
   第一遍走到那里时映射表里还没有这个名字（这一条是新增测试自己抓出来的）。
3. 新增 `tests/css-modules.test.ts`（7 项）**断言变换自己的输出**：声明值里不得出现作用域前缀、
   关键字值数量不变、`column` 值数量不变、`:global()` 原样回填、动画值引用的是加了前缀的 keyframe 名。
4. 新增 `npm run preflight` 的**产物**检查：构建产物里若出现 `flex-direction: _xxx_column`
   这类"类名进了声明值"，直接判失败；同时要求 flex column 数量达到阈值。
5. 我这次视觉复核用的一条可复用路子也留下来了：`preview/dump.tsx` 在 happy-dom 里挂载**真 Reader**，
   把真 DOM 导出成静态页，再交给无头 Chrome 用**真宿主 token + 构建产物的哈希样式表**布局。
   本地预览用的是 `scopeCss(css, '')` 那条老路——它看得见的，这条新路都看得见；它看不见的
   （前缀相关的 bug），这条新路也看得见。

**教训一句话**：变换器的正确性只能在**变换后的产物**上验证；用源码、用桩、或用恒等配置去验证，
得到的都是"我没问题"。

## 事故二：一个 `position: relative` 造出的"幽灵滚动范围"（2026-09-29）

**现象**：装好之后阅读页先是**一片空白**，接着"滚动逻辑诡异、整个界面互相遮盖、输入框也跟着滚"。

**根因**：v5 为了给"窗口四角"找锚点，写了一条

```css
[data-deckseek-skin='terminal'] .column { position: relative; }
```

给 `.column` 定位，就让**它成为内部所有绝对定位元素的包含块**。而这个列里面装着工具行的"语言"：
`.srOnly` 辅助文本、折叠的 `.toolState` 标记、每行的 `.branchReason` 标签 —— **大约九十个 1px 的绝对定位盒子**。
它们原本锚在宿主的根节点上、待在原地；列一旦定位，它们改锚到 `.column`，于是**从"执行过程"那块 400px 高的
裁剪容器（`max-height: 400px` + `overflow-y: auto`，正常会吞掉 11000px 的过程）里被抬了出来**。它们的静态位置
深在那段过程里，于是列的**可滚动溢出**直接等于整段过程的高度，宿主的滚动条继承了这个虚空区间 ——
文字读完以后还能往下滚几万像素。

**这也解释了"空白"**：插件恢复阅读位置（`useReadingPosition`）时，落在那个什么都不存在的区间里。

**在真实应用里量到的**（同一会话、同一时刻，只改这一条声明）：

| | `.column.scrollHeight` | 宿主 `.scrollBody.scrollHeight` | `.column` 的 `position` |
|---|---|---|---|
| 改前 | 12310 | 12327 | `relative` |
| 改后 | 2107 | 2261 | `static` |

逐层二分定位到的溢出链：`.column` → `.turn` → `.mainFlow`（400px 裁剪）→ `.flowContent`（**11635px**）→ …
每一个 1px 盒子单独改回 `static` 都看不出变化 —— 因为 `scrollHeight` 取的是**并集**，只要最深的那一个还在外面，
区间就不会缩短。这也是它骗过截图、骗过测试、而且"看起来只是有点怪"的原因。

**修法**：插件内**任何祖先都不得成为包含块**。

- 四角改画在两条本来就 `position: sticky` 的栏上（`.topBar` 出上面两个、`.statusBar` 出下面两个）——
  sticky 元素本来就是定位元素，白捡一个锚点，不额外收养任何后代。四角统一 12px 字号，圆心落在边框角上。
- 纹理层（`.screenTexture`）以前靠列的定位做 `inset: 0` 覆盖，现在改成 `position: sticky; top: 0;
  height: 100vh; margin-bottom: -100vh`：它本来就是"屏幕"的纹理而不是"日志"的纹理，钉在可视顶部、铺满一屏、
  负外边距抵消占位。
- 新增 `tests/skin-css.test.ts` 的守卫用例：**terminal 皮肤下 `.column` 不得出现任何 `position`**
  （`static` 除外），并检查四角确实挂在两条栏上、纹理确实是 sticky。

**教训一句话**：给容器加 `position: relative` 不是"局部改动"。它改写的是**所有后代**的包含块，
而包含块决定谁能被裁剪 —— 一个只为画四个角而加的声明，代价可以是整个视图的滚动范围。

## 事故三：同一条规矩守住了，同一个 bug 还是回来了（2026-09-29）

事故二的修法给纹理层留了一句"不能靠定位的列，改 `sticky`"。那句话守住了它要守的东西
（列确实没被定位），**却把 bug 从另一条路放了回来**。

**现象**：`skin: terminal` + `texture: crt` 下阅读页空白、会话一开就"黑了"；关掉纹理即好。

**根因**：`sticky` 确实不收养后代，但它**照常参与列的布局**。`height: 100vh` 配
`margin-bottom: -100vh`，只有在**列本身高过一屏**时那点占位才被抵消干净。列比一屏短的时候
（新会话、短历史 —— 恰好是用户第一次打开纹理档时的状态），这个 100vh 的盒子就是列里最高的
东西：列的滚动溢出等于一屏，而文字一百像素就到底。`useReadingPosition` 恢复的位置落进这段
空区间，就是那片空白。**与事故二同一个失败类，只是换了条路径，而且这次只有显式开纹理的人会踩。**

**真 Chrome 实测**（构建产物里 8 张样式表 + 真 Reader DOM，加宿主滚动容器）：

| 配置 | 列内容高 | 纹理盒高 | 宿主 `scrollHeight` / 可视高 | 溢出 |
|---|---|---|---|---|
| `texture=off` | 311 | 0（`display:none`） | 813 / 813 | 0 |
| `texture=crt`（修前 sticky） | 319 | 813 | 840 / 813 | **27px 虚空** |
| `texture=crt`（修后 fixed） | 311 | 813 | 813 / 813 | 0 |

**修法**：`position: fixed; inset: 0` —— 唯一**既不算包含块、又不占布局**的定位方式。
另实测 `.root` 的 `container-type: inline-size` 在 Chrome 下**不**让 fixed 子元素以 `.root`
为包含块：纹理仍是视口尺寸（613 = 视口高，而非 `.root` 的 192），滚动后仍钉在 `top: 0`。
所以"钉在屏幕上"的观感不变，只是它再也不参与列的高度计算。

**这次真正要改的是防线口径。** 原守卫断言的是 `position: sticky` 这个**实现方式**：

```js
assert.match(bare, /position:\s*sticky;\s*top:\s*0;[^}]*height:\s*100vh/, '…');
```

它把"我当时选的修法"当成了正确性，于是"这个修法本身有 bug"再没有人问 —— 同一层为同一个 bug
修了两次。改成断言**结果**：

- 新增 `no full-height layer can occupy the column's flow`：列/根/纹理这一族里，凡
  `height: 100vh | 100dvh` 的规则都必须是 `fixed` / `absolute`。它不关心你选了哪种定位。
- 纹理那条断言从 `bare.split('display: block')[1]` 的**空洞查找**改成按规则自身特征定位。
  旧写法切到的是文件里**另一条** `width: 18px; height: 6px` 的规则，`exec` 取到 `null`，
  后面整段 `layer === null || …` 全部**空转通过**。**一条会空转的绿守卫，比没有守卫更坏。**

两条新守卫都用"把 `sticky` 放回去"验过会 `fail`（298 → 296 fail 2）。
**教训一句话**：守卫要钉**结果**，不要钉**修法**；写下修法的那一刻，你就再也看不见它了。
